# Vorpal embedding and ranking implementation

Inspected 2026-09-10 against the clean local `../vorpal` checkout at [`4dd203fa560bfd2c0c8f1857f7bbca983c23de63`](https://github.com/hyper-light/vorpal/tree/4dd203fa560bfd2c0c8f1857f7bbca983c23de63). This note follows implemented production branches, not the proposed architecture in `docs/wip`. No indexing, model inference, benchmark runs, or server changes were performed.

## The important distinctions

| Path            | Input and output                                                                                                 | What it does                                                                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default lexical | Identifier-like tokens → 256-dimensional, L2-normalized signed hash vector                                       | Supplies the base vector candidate list; no training or model download.                                                                                 |
| Learned static  | Corpus-trained word/subword vectors → corpus-selected dimension, normally 64–256, L2-normalized text embedding   | Replaces the base text embedder. Build-time graph retrofit also modifies stored document rows. Not a neural reranker.                                   |
| CodeRankEmbed   | WordPiece tokens → NomicBert → final **CLS** vector → L2 normalization; 768 dimensions for the distributed model | Separately supplies a background-built dense candidate channel and a query-time reranker. It is a bi-encoder, not joint query/document cross-attention. |

Sources: [default embedder](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/embed.rs#L42-L108), [learned dimensionality and factor construction](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/model.rs#L576-L607), [encoder pooling/normalization](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/forward.rs#L752-L770), and [upstream pooling configuration](https://huggingface.co/nomic-ai/CodeRankEmbed/raw/main/1_Pooling/config.json) (live primary-source cross-check: 768, CLS enabled, mean pooling disabled).

## 1. Default: feature hashing

- Split on non-alphanumeric boundaries and lower-case/numeric → upper-case boundaries; lowercase tokens. This is a bag of identifier-like words, **not character trigrams**. Both name matching and this embedder share these boundary rules.
- Hash each token with FNV-1a. Derive a second hash by multiplying by `0x9E3779B97F4A7C15` and rotating left 31 bits. Each hash selects a coordinate modulo the dimension and adds `+1` or `−1` according to one hash bit. Repetition accumulates; collisions are possible.
- Normalize the resulting vector to unit L2 length; empty input remains zero. Default dimension is 256; the constructor permits other dimensions with a minimum of 8. [Implementation](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/embed.rs#L42-L186).

Document inference uses **`name name signature basename`**, so the name has double weight. File-node names have the checkout root stripped; the last path component is used separately. It does not embed complete source bodies or arbitrary full paths. Queries embed their text directly, without a task prefix. Import nodes are excluded from the vector row universe, although the name channel can still return them. [Row universe and node recipe](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L2104-L2168), [query embedding](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5801-L5819).

## 2. Learned: corpus statistics, then graph refinement

Training streams **`name signature basename`**, with the name once, over non-Import nodes. The production `BalanceToCallables` policy caps overrepresented kinds at the largest Function/Method/Constructor population using deterministic sampling. This is not training on whole files or downloaded natural-language examples. [Training corpus](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L3114-L3216), [active policy](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L4291-L4298).

The implemented pipeline:

1. Shared word tokenizer; words appearing fewer than five times have no dedicated matrix row. Add boundary-marked character n-grams of lengths 3–6; omit the gram equal to the entire wrapped word. Grams are interned exactly until the two-million-bucket bound requires hashing.
2. Count symmetric, within-document co-occurrences with a two-token window; gram rows share word contexts. Form positive PMI with context-distribution smoothing exponent 0.75 and no shift. The code averages the two smoothing directions to keep the matrix symmetric.
3. Seeded randomized symmetric factorization; scale factor coordinates by the square root of singular-value magnitude. A PIP-loss criterion, using half-split noise estimates, chooses dimension. The desired clamp is 64–256, **but rank-deficient corpora may produce fewer than 64 factors**. Unsupported corpora explicitly fall back to lexical.
4. Compose each token from its word row plus gram rows; unseen words use known grams alone. Subtract the learned mean and top `ceil(d/100)` components (ABTT), then normalize each token vector.
5. Pool token vectors with uSIF weight `a / (p(token) + a/2)`, averaging over input token count. Remove weighted projections onto up to five common sentence components, then L2-normalize the document/query vector. If no token is representable, return zero.

Sources: [training constants](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/model.rs#L27-L42), [subword implementation](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/subword.rs#L10-L55), [symmetric PMI](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/cooc.rs#L159-L186), [factor selection](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/model.rs#L576-L607), [inference pipeline](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/model.rs#L178-L272), [postprocessing formulas](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/pool.rs#L1-L28).

Node inference uses the same double-name recipe as hashing; queries use the same learned text embedding pipeline without a special prefix. The model is trained at warm time and checksum-verified/mapped at query time, not trained for each query. [Active embedder](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L2208-L2260), [owned/mapped model adapter](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/learned/embedder.rs).

**Graph retrofit is a separate build-time operation.** It retains an anchor penalty while pulling document rows toward graph neighbors. Edges must pass confidence rules; zero-signal rows and hubs are excluded. Relation weights come from mean anchor similarity and are degree-normalized. Production uses the identity penalty, not fitted per-relation diagonal maps; NUDGE is disabled. The Jacobi update is `x_i ← (q_i + Σ w_ij x_j) / (1 + Σ w_ij)`. This is not an MLP applied to a hash vector. [Edge construction](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L3267-L3295), [active forms](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L3496-L3526), [solver](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/retrofit.rs#L142-L237).

Precision detail for diagrams: the retrofit solver does not re-normalize its outputs. Those rows enter ANN construction, while query vectors remain learned text embeddings. Bounded candidate sets are subsequently re-embedded from node text and ordered by full-precision squared L2; learned full-population scans instead retain code-space ordering. Do not depict every stored/refined vector as unit length or the final semantic score as always a cosine against the graph-refined row. [Stored rows](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L3680-L3709), [serving branches](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5905-L5975).

## 3. Neural: CodeRankEmbed, with two document surfaces

Vorpal owns the tokenizer and NomicBert inference implementation. It loads model/config/tokenizer files, checks supported configuration and tensor shapes, and runs no Python service. The distributed artifacts are downloaded from Nomic's CodeRankEmbed repository and pinned by SHA-256/size; URLs use `main`, but verification rejects changed bytes. The encoder dimension is read from `n_embd`, not a hard-coded output projection. The distributed model is 768-D. [Loader](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/mod.rs#L150-L224), [artifact pins](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/models.rs#L106-L129), [local dimensionality reference](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L2514-L2519).

- Tokenization: configured BertNormalizer → BertPreTokenizer → greedy WordPiece → `[CLS] text [SEP]`. Unlike the lexical tier, this is not the shared camel-case tokenizer. Long sequences are tail-truncated to the model's trained position budget, preserving `[SEP]`.
- Forward: word/token-type embeddings, layer normalization, bidirectional self-attention with rotary positions, post-normalized residual blocks and SwiGLU. Pool the final hidden state at **CLS**, then L2-normalize. Batched queries/documents retain separate attention boundaries; they do not attend to one another.
- Query only gets `Represent this query for searching relevant code: ` before tokenization. Documents get no task prefix. These are two applications of the same model, compared by dot product after normalization.

Sources: [tokenizer](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/tokenizer.rs#L1-L10), [clamp, batching and query prefix application](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/mod.rs#L411-L467), [forward architecture](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/forward.rs#L1-L32), [attention block bounds](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/forward.rs#L528-L550).

**Dense retrieval:** embed `name signature basename` plus the leading comment and the definition span's first paragraph. The richer extra text is trimmed toward a 398-token surface budget; a long head is ultimately bounded by the encoder clamp. Unavailable/changed source falls back to the head surface. Background filling covers referenced non-Import definitions, descending by referential in-degree, with resumable checkpoints. It runs only with a configured encoder; a fresh partial sidecar can serve immediately. It is on by default when available, with a per-index opt-out. [Recipes and coverage](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/dense.rs#L80-L212), [surface builder](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/dense.rs#L354-L442), [default-on gate](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L2632-L2649).

**Reranking:** encode only `name signature basename`, each name once, for cache-missed candidates. A bounded per-generation cache reuses document vectors. Reuse the already-computed dense query vector where available. Query inference uses fixed-order CPU numerics; background document inference selects GPU → platform GEMM → fixed-order CPU. f16/f32 name weight-file precision, not vector dimension or different pooling. [Two surfaces](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/dense.rs#L123-L156), [reranker](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5499-L5598), [inference execution paths](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/encoder/mod.rs#L1-L39).

## 4. How vectors become results

**Base vector index:** automatic selection is flat exact at ≤65,536 rows, otherwise Vamana. Vamana stores per-row scaled int8 vectors plus mmap-backed CSR navigation edges; it is not the knowledge graph itself. The shipping code does **not** implement IVF sharding. A one-bit flat-quantized tier exists but is not auto-selected. An old comment says Vamana uses full-precision traversal; current construction and quantized distance code supersede it. [Actual selection and format](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/index.rs#L14-L76), [actual build](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/index.rs#L282-L303), [distance algebra](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/qmatrix.rs#L1-L16), [IVF explicitly future](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/lib.rs#L1-L15).

**Neural sidecar:** a different index, `ann.dense`, stores int8 codes, scales and f16 rows. It scans admitted rows by integer dot product, retains `4 × pool`, then rescales/reranks that shortlist using f16 rows widened to f32 and a fixed-order dot with the f32 query. This does **not** use Vamana or IVF. [Dense algebra](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/dense.rs#L1-L38), [serving implementation](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/dense.rs#L1064-L1098).

**Fusion:** name matching, base vector similarity and referential in-degree supply three ranked lists. The degree list reranks **name candidates only**, not all popular graph nodes. Per-corpus-gated BM25 can contribute a fourth list, the fresh neural sidecar a fifth. A conditional source-body list can also nominate candidates when name/BM25 have none. The ordinary candidate-list depth is `max(4k, 50)`. [Pool size](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L3950-L3957), [channel construction](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L6039-L6150), [list assembly](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L4910-L4968).

For candidate `d`, production reciprocal-rank fusion is `score(d) = Σ 1 / (60 + r_c(d))`, where `r` is **zero-based** and a missing placement contributes nothing. Sort descending, break ties by node ID, retain top `k`. Dense fusion is the same plain formula, not raw cosine addition or a learned weighting. User-facing channel ranks are one-based, so a displayed rank `p` contributes `1/(59+p)`. [RRF implementation](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L4328-L4365), [dense law](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L4226-L4243).

Finally, the optional neural reranker **pins the fused winner** and reorders only the rest of that already-fused top `k` by neural cosine. It cannot introduce a missing candidate. Reported RRF scores/channel ranks remain unchanged even if result order changes. Conjunction queries keep their separate min-RRF contract and bypass this rerank. [Search order](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5449-L5467), [winner pin and ranking](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5477-L5635).
