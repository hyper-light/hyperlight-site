## The central distinction

Vorpal is not a replacement parser or just a directory of cached syntax trees. Its Rust pipeline uses Tree-sitter and the ast-grep-derived pattern engine to extract a reusable code model, resolve relationships across files, publish an index, and serve graph, structural, text, and ranked queries over it. The useful article explanation is: **a syntax tree describes a file; the extra machinery makes repository questions answerable repeatedly.** This is an architectural interpretation of the concrete stages below, not a claim that other Tree-sitter-based systems cannot build the same capabilities.

## Implemented flow

```text
source tree → manifest / cached extraction decision → parse + extract
            → definitions + reference/type/argument facts → resolve + link
            → bucketed graph generation → CURRENT publication
            → generation-pinned query handles + optional retrieval sidecars
            → CLI / MCP / library callers
```

1. **Discover and decide what changed.** The ignore-aware parallel walker records accepted files' path, size, and mtime. The indexer canonicalizes the source root, incorporates grammar/rule identity into reuse checks, and can use a complete watched change set instead of another full walk. Fast-stat mode has a documented blind spot for same-size edits whose mtime is deliberately preserved outside its racy window; `vorpal index . --verify` reads candidate contents to validate reuse. Unchanged trees can retain the entire generation. [Manifest](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/manifest.rs#L35-L120), [root and identity](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L518-L573), [cache policy](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L140-L175).

2. **Parse and extract once for that product.** `OutlineExtractor` selects the language from the path, parses through `grep_cached`, and derives outline items, references, type facts, argument/return information, source spans, and signature sketches. The streaming path encodes borrowed extraction directly into product bytes instead of allocating a second owned object graph. An existing scan tree can feed extraction without another read or parse. Outline rules are lazily compiled per language and shared within the process. [Extraction entry points](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/outline_extractor.rs#L460-L561), [rule reuse](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/outline_extractor.rs#L29-L86).

3. **Resolve repository relationships.** The linker builds a symbol table with file, owner, kind, and visibility information; import nodes are wiring, not candidate definitions. Resolution uses import paths/include reachability, qualifiers, local definitions, visible exports, and conservatively inferred receiver types. Outcomes retain confidence/grade, resolver reason, occurrence span, candidate count, and bounded alternatives. Ambiguous candidates can yield a deterministic **heuristic** edge; unresolved or masked uses do not become proven calls. Confidence values are implementation categories, not calibrated probabilities. [Symbol table](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/pipeline.rs#L1738-L1825), [grades and reasons](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/resolve/src/resolver.rs#L10-L115), [retained evidence](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/resolve/src/resolver.rs#L193-L243).

4. **Seal and persist.** Extraction products, nodes, edges, evidence, usage, and signature families use the default bucketed layout; unchanged buckets can be hard-linked into successor generations. A staged generation is content-addressed and published through an atomic `CURRENT` pointer change. Queryable node/heap slabs and graph adjacency can be memory-mapped; `graph.bin` is validated against its node and edge families. Optional ANN/text sidecars have their own freshness checks rather than defining the generation's identity. This is a local binary store, not a requirement to run an external graph database. [Format contract](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/docs/INDEX_FORMAT.md#L5-L55), [persistence](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L1258-L1303), [graph loading](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/kg/src/kg.rs#L1916-L1950).

5. **Compose edits instead of necessarily rebuilding everything.** After whole-tree reuse, the current indexer tries an extraction-identical stamp cutoff, span-only compose, definitions-stable/body-edit compose, and definitions-changed compose with affected usage closure. Each has eligibility gates and can fall back to the complete pipeline. Bulk references are spilled and resolved in bounded chunks. Bounded in-flight work is **not constant total memory**: the source explicitly excludes the growing output graph from that budget and enforces 32-bit node/string-heap limits. [Compose lanes](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L722-L795), [reference spill](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/pipeline.rs#L2262-L2315), [memory budget](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L115-L138), [hard limits](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L1106-L1127).

6. **Query the right representation.** Graph tools traverse resolved relations; `query` is a bounded, read-only Cypher-shaped language, not full Cypher. Ranked search uses the channels below. Structural search still uses AST matching, but can prune with text-index literals, parse only eligible statement chunks, replay match memoization, or answer supported bare call shapes from verified extraction references without reparsing. Source snippets read the actual source with index-digest verification. [Query grammar/ceilings](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/query/src/lib.rs#L1-L49), [structural fast paths](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/tools.rs#L185-L262), [source tool contract](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/docs/mcp.md#L269-L280).

## Tree-sitter: exactly what to say

- The workspace selects Tree-sitter 0.26.3 and patches it to its vendored runtime; grammars are vendored too. The language matrix lists 49 language entries, with **separate** parser, outline, reference-extraction, and relation-fixture columns. Some languages are structural-only. The seven fully labelled relation fixtures are C, C++, Go, Java, Python, Rust, and TypeScript; their fixture scores must not become a claim of universal resolution precision. [Dependency selection](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/Cargo.toml#L55-L74), [matrix](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/docs/LANGUAGES.md#L3-L70).
- A normal fresh document calls `Parser::parse(bytes, None)`. Per-worker parser reuse retains parser allocation pools, **not automatically every file's prior tree**. Outline traversal dispatches compiled rules by node kind; embedded-language injections use included ranges and preserve host-file byte offsets. [Parser reuse](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/core/src/tree_sitter/mod.rs#L30-L104), [outline traversal](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/outline/src/combined_extractor.rs#L1-L13), [injections](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/outline_extractor.rs#L580-L610).
- There is also a process-local giant-file tree cache: default floor 1 MiB, retention after a second encounter, LRU budgeting of retained source and walk snapshots. A subsequent edit clones/edits the prior tree with one spanning `InputEdit`, then parses with that seed and can reuse extraction-walk rows. This is distinct from the on-disk extraction-product cache. It is not a promise that every save only visits changed AST nodes; multiple edits become one spanning replacement, eligibility can fail, and tree memory is additional to the source/snapshot budget. [Cache policy and promotion](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/tree_cache.rs#L27-L108), [cache execution](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/tree_cache.rs#L140-L226), [incremental parse](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/core/src/tree_sitter/mod.rs#L154-L225).
- Parsing is not type-checking, executing a build, or proving every possible runtime call. Vorpal's additional static resolver is explicitly graded. Parse damage is measured from Tree-sitter `ERROR` nodes with warn/exclude/fail policies; a tree containing only `MISSING` nodes does not increase that ERROR-byte metric. Avoid “understands everything” or “complete call graph.” [Error accounting](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ingest/src/outline_extractor.rs#L594-L610), [parse policies](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L179-L219).

## Hybrid retrieval, without hand-waving

Default vector representation is **lexical**, not a neural model: split punctuation and lower-to-upper camel humps, lowercase, add two signed hashes per token to 256 buckets, then L2-normalize. Node input is `[name, name, signature, basename]`; file-node names lose the checkout-root prefix. Thus identifier words contribute twice, and ordinary vectors do not embed entire function bodies. Unit-vector squared L2 distance orders the lexical candidate pool. [Hasher](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/embed.rs#L42-L108), [node surface](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L2151-L2167), [distance reranking](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5943-L5975).

The base lists are:

1. **Name:** exact spelling, then identical token sequence, then names containing all query tokens; shorter names and IDs break ties.
2. **Vector:** lexical or explicitly selected learned-model neighbors.
3. **Graph:** the **name candidates only**, ordered by referential in-degree. It disambiguates similarly named definitions; it does not reward unrelated popular symbols.

For a candidate `d`, current plain fusion is `score(d) = Σ[c containing d] 1 / (60 + rank_c(d))`, with **zero-based** ranks. First place contributes `1/60`, not `1/61`. Missing channels add zero; descending score then ascending node ID determines the fused order. [Name/graph implementation](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5978-L6053), [fusion](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L4328-L4365).

BM25 and dense-code lists are optional/per-corpus gated. A conditional body list runs when name and BM25 results are empty; it needs complete trigram candidate coverage, verifies source bytes, considers tokens at least three bytes long, and bounds work by the pool. The optional code encoder normally keeps the fused winner and reorders the tail by cosine; recorded RRF scores remain unchanged. Therefore neither “always exactly three channels” nor “everything is a neural embedding” describes the current pipeline. [Extra lists/body conditions](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L6055-L6150), [encoder ordering](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5477-L5528).

ANN chooses exact flat scan through 65,536 rows and Vamana above that; its approximate pool is not a recall guarantee. Search can use a fresh tier, reconcile edited files through an overlay, or fall back to exhaustive scoring while scheduling warm-up. Approximate paths overfetch and then apply filters; the old blanket pre-filter comment should not be repeated. Exact scoring **within a selected pool** does not recover a candidate the approximate search never found. [ANN selection](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/ann/src/index.rs#L14-L38), [routing/filter behavior](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L5822-L5855).

## Why a persistent server helps—and when it does not

The real saving versus repeated raw parsing is retaining **derived answers and query-ready structures**, not merely leaving a parser running. Generation-pinned `Searcher` handles reuse graph, ANN, and posting mappings; a process-wide bounded cache avoids reopening them for each request. MCP also retains live pre-link state, an editable graph overlay, and an ANN update tier. Its stdio loop wakes every 250 ms; after a quiet save window, proactive work can move rebuild cost before the next query. [Searcher cache](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L6331-L6386), [retained server state](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L149-L196), [stdio pulse](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/lib.rs#L111-L165).

Important qualifications:

- A one-shot CLI query already reads the persisted index; it does **not** rebuild/parse the repository on every invocation. A cached Tree-sitter service can likewise reuse trees. Vorpal adds reusable extracted products, resolution, retrieval structures, and a query protocol; do not credit all persistence benefits uniquely to MCP.
- Keeping overlays/models warm costs resident memory and background CPU. Large edits, missing caches, custom extraction environments, and unsupported deltas can fall back to full work. A query can wait for an in-flight refresh or generation-bound persistence; “always instant” and “never blocks” are not supported. [Refresh/drain rules](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L1207-L1299), [generation-bound tools](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L1819-L1859).
- Automatic root watching requires the `<source>/.vorpal/index` layout. An arbitrary custom index location has no inferred watch root and needs explicit refresh. Watcher delivery is not instantaneous; stat backstops/reconciliation mitigate missed events. A “read-only” tool profile restricts callable tools, not all internal index/cache writes. [Root inference](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L3256-L3271), [backstop](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L1224-L1255), [profile membership](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L66-L79).

## Two syntax-checked examples

### 1. Index, find, and follow a relationship

With `vorpal` installed, run **from a Vorpal source checkout**:

```sh
vorpal index .
vorpal search "stat manifest change detection" -k 5 --format json
vorpal graph callers resolve_import_path --path crates/resolve/src/resolver.rs --format json
```

These names refer to the inspected code; no expected output is fabricated here. `index .` writes `.vorpal/index`; queries default to that path relative to the shell. `--path` is a **suffix** filter. CLI references are `graph refs` and `graph typeusers`, unlike MCP's `references` and `type_users`. [Index arguments](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/cli/src/kg.rs#L75-L88), [graph selector](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/cli/src/kg.rs#L208-L248), [search arguments](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/cli/src/kg.rs#L296-L342), [argument-parser tests](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/cli/src/lib.rs#L211-L239).

### 2. Ask the same question over MCP stdio

From that same checkout, this executable shell example uses the supported legacy handshake, sends newline-delimited JSON-RPC, and closes the short demonstration session at EOF. A normal MCP client instead owns and keeps the process open.

```sh
vorpal mcp --index "$PWD/.vorpal/index" --profile analysis <<'JSONL'
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"vorpal-example","version":"1.0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"graph","arguments":{"relation":"callers","name":"resolve_import_path","path":"crates/resolve/src/resolver.rs","format":"lean"}}}
JSONL
```

The tool is `graph` with a `relation`, **not** a separate `callers` tool. Its absolute default-layout path makes the source root derivable. For client setup without writing anything first, `vorpal mcp install --client cursor --dry-run` is a supported inspection command; omit `--dry-run` only when intentionally installing the config. [MCP CLI](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/cli/src/kg.rs#L345-L396), [graph schema](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/server.rs#L2902-L2923), [stdio/legacy-handshake process test](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/tests/stdio.rs#L54-L92).

## Documentation/code mismatches to avoid carrying forward

- `docs/wip/ARCHITECTURE.md` explicitly labels itself a July 1 **design/proposal**. Its 28-language baseline, billion-LOC target, flat-total-memory aspiration, proposed storage/ANN packages, `rmcp`, and leaked singleton are not a current implementation inventory. Current MCP uses a mutable server with `Arc`-held state and direct `serde_json` protocol handling. [Proposal](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/docs/wip/ARCHITECTURE.md#L1-L46), [actual protocol](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/mcp/src/lib.rs#L1-L12).
- `crates/index/src/lib.rs` lines 3–5 say the graph is “always re-linked”; the newer compose lanes above supersede that description. Lines 4388–4389 describe graph candidates as the name/vector union, contradicted by the current name-only implementation at 6039–6053. The nearby claim that filters precede every ranking tier is also broader than the current ANN overfetch/post-filter implementation. Trust executable branches over those comments.
- `Kg::load`'s introductory comment says it reads the heap and rebuilds CSR/CSC, but the current code maps a valid graph cache and only rebuilds when necessary. Likewise the learned-training comment says `All` remains pinned while `LEARNED_TRAIN_KINDS` actually selects `BalanceToCallables`. Avoid copying stale implementation comments as policy. [Loader](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/kg/src/kg.rs#L1916-L1947), [actual training constant](https://github.com/hyper-light/vorpal/blob/4dd203fa560bfd2c0c8f1857f7bbca983c23de63/crates/index/src/lib.rs#L4270-L4297).
- Source comments link `docs/UPSTREAM.md` and `docs/EMBEDDING.md`; those files are currently under `docs/wip/`. Use the real paths when linking.

Suggested article framing: **“Start with syntax, keep the relationships, answer from the index.”** Demonstrate a search followed by callers and source evidence; explain the warm-server benefit in repeated-question workflows; retain the distinctions between parsing, static inference, ranked retrieval, and measured benchmark results.
